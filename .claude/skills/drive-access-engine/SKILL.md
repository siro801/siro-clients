# מנוע גישה אוטומטית לקבצי דרייב — SIRO

## מה זה
לקוח מקבל **קישור/נקודת כניסה אחת**. מי שנרשם מקבל **אוטומטית** גישת צפייה פרטית
לקבצי דרייב למייל שלו, וכל הרשמה **נרשמת בגוגל שיטס**. אותו מנוע לכל לקוח —
משתנים רק המיתוג, הקבצים, ודרך השליחה.

## קבוע בכל מופע (לא לשאול — זה המנוע)
הקהל **תמיד מסונן** (NetSpark/נטפרי/Safer/הדרן). מכאן:
- נקודת כניסה = **מייל (מילת מפתח) או וואטסאפ** — לא טופס ציבורי באתר.
- מסירה = **הרשאת reader פרטית per-user** בלבד. לעולם לא "כל מי שיש לו הקישור".
- חסימת דומיין לא נפתרת בקוד → להזכיר ללקוחה **הלבנת דומיין** מול חברת הסינון.

## כשמפעילים — סדר הפעולות

### שלב 0 — פתיחת תיקיית לקוח
1. שאל שם לקוחה. ב-repo `siro-clients` צור **תיקייה חדשה** לכל לקוחה: `clients/<slug>/` (slug באנגלית, קטן, מקפים).
2. בתוכה: `intake.md`, `config.json`, `email-template.html`, `workflows/`, `entry/`, `README.md`.

### שלב 1 — שאלון אפיון
שאל **רק מה שחסר**. אל תניח. שמור כל תשובה ל-`intake.md` וממלא במקביל את `config.json`.

**מיתוג**
- שם מותג לתצוגה · צבעי מותג (hex) + לוגו · פונט.
- מייל שולח (קיים / להקים) · שם+מייל ליצירת קשר לפוטר.

**קבצים**
- כמה קבצים לנרשם · סוג (וידאו/אודיו/PDF/מעורב) · גודל משוער.
- קבוע או מתעדכן · כולם מקבלים אותם קבצים או קבוצות/רמות.
- מיקום הקבצים (Shared Drive קיים / להקים).

**דרך שליחה**
- מייל אחד עם הכל / מייל נפרד למנה · נוסח קיים או לנסח · שפה+כיווניות (ברירת מחדל עברית RTL).

**נקודת כניסה**
- מייל (מילת מפתח, ברירת מחדל "גישה") / וואטסאפ / שניהם.
- יש תשלום לפני גישה? איך מאומת (סולק / ידני / רשימה קיימת).

**רישום**
- שדות לשיטס (שם, מייל, טלפון, תאריך, מקור, קבצים שנשלחו) · צריך רשימת דיוור נפרדת.

**גדילה**
- צפי כמות נרשמים · **וידאו כבד?** אם כן → הדלק **מודול רוטציית דורות** (שלב 4ד) ושאל סף (ברירת מחדל 18).

**אירוח** (ראה שלב 5)
- דף כניסה אצל SIRO / אצל הלקוחה · דומיין קיים של מי.

### שלב 2 — תשתית גוגל
הנחה/הקם: Shared Drive + העלאת קבצים; Google Sheet עם 3 לשוניות — `הרשמות`, `config` (Drive ID פעיל ב-B2, מספר דור ב-A2), `רשימת דיוור`. שמור Sheet ID + config GID ל-`config.json`.

### שלב 3 — דף כניסה (רק כשצריך)
קהל מסונן = כניסה דרך מייל/וואטסאפ, ולרוב אין צורך בדף. בנה דף **רק אם הלקוחה ביקשה** דף הסבר + כפתור "שלח מייל לגישה". אם כן — ל-`entry/`, ואם מתארח אצל SIRO תת-נתיב ב-repo האתרים.

### שלב 4 — בניית n8n
n8n מחובר דרך **MCP** → בנה את ה-workflows **ישירות דרך ה-MCP**. שמור עותק JSON של כל workflow ל-`workflows/` (גיבוי + מעקב גרסאות ב-git). קרדנציאלס (Google/Gmail) מתחברים ידנית בתוך n8n. אם ה-MCP לא זמין בריצה מסוימת — נפילה ל-JSON ל-import עם המלכודות מתוקנות (שלב 6).

בנה תמיד:
- **A — מתן גישה:** כניסה → חילוץ שם+מייל → רישום בשיטס → הרשאת reader → מייל ממותג.
- **D — הרשמה ממייל (קהל מסונן):** Gmail trigger על מילת מפתח → A. כולל מענה אוטומטי לבקשות שיתוף דרייב.

בנה לפי צורך: **B** (שליחה חוזרת / החלפת קבצים), **C** (דיוור לכל הרשימה).

**ד. מודול רוטציית דורות — רק אם וידאו כבד:**
config מחזיק Drive ID פעיל + מספר דור. הפלואו סופר הרשאות reader לכל דור (ראה שלב 6), בוחר את הדור הישן ביותר עם פחות מהסף, ופותח דור חדש כשמגיעים לסף. המלצת קידוד: ~720p, 1.25–1.5x, ~1.5–2.5GB.

### שלב 5 — אירוח הקישור
הקישור המתפרסם = נקודת הכניסה. ה-n8n רץ ברקע, ה-Webhook לא נחשף.
- **SIRO:** תת-נתיב `sirosystems.com/<לקוח>/` (סטטי, Cloudflare Pages).
- **לקוחה:** Hostinger (~25 ₪/חודש) או קיים. דומיין **חייב להיות של הלקוחה וקיים** — SIRO לא רוכשת דומיין.
- קהל מסונן: אם הכניסה היא מייל/וואטסאפ בלבד — ייתכן שאין צורך בדף מתארח; אם יש דף — לוודא שהדומיין מולבן מול הסינון.

### שלב 6 — בדיקה מקצה לקצה
הרשמת בדיקה: רישום → הרשאה → מסירת מייל → צפייה בקובץ. לוודא שכל הקבצים מופיעים במייל.

### שלב 7 — commit + push
`git add clients/<slug>` → commit עם הודעה `feat(<slug>): drive-access engine` → push ל-repo `siro-clients`. דווח לסימי: הקישור, מיקום התיקייה, ומה נבנה.

## מלכודות — לבדוק לפני מסירה
- `files.list` עם `fields=permissions` מחזיר מערך ריק בשקט → לספירת הרשאות `permissions.list` לכל קובץ בנפרד.
- כל קריאות Drive API: `supportsAllDrives=true` + `includeItemsFromAllDrives=true`.
- מתן גישה: `POST /files/{id}/permissions` עם `sendNotificationEmail=false`, `role:reader`, `type:user`.
- import JSON לקנבס לא ריק מוסיף "1" לשמות ולא מעדכן `$('NodeName')` ב-Code nodes.
- קרדנציאל placeholder (REPLACE_ME) → שגיאת "Missing credential" קבועה. להקצות UUID חדש ל-id לפני import.
- Gmail Send דורש במפורש `resource:"message"`, `operation:"send"`, `emailType`.
- `$getWorkflowStaticData('global')` נשמר רק ב-Active, לא בהרצת בדיקה.
- מיילים ב-Sent אך לא מתקבלים → חשוד ראשון: חריגת מכסת שליחה יומית מריבוי הרצות בדיקה. לבדוק "Show original".
- חילוץ מייל מהתראות שיתוף: לשרשר snippet+subject+text+html, regex למייל, לסנן `@google.com` ואת דומיין השולח.
- קרדנציאלס מתחברים **ידנית** אחרי import. עריכות כירורגיות ל-JSON קיים, לא לבנות מחדש.
